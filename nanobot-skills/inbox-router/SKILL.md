# 微信收件路由

收到由微信 iLink 收件服务提供的消息时：

1. 保留原文中的事实、URL、日期、人名和文件名，不要推测附件中未读取的内容。
2. 明确包含“待办、提醒、截止、记得、todo、要做”的内容优先归为 `task`。
3. 网页、文章或资料链接归为 `reference`；文档附件归为 `document`；没有更合适类型时归为 `inbox`。
4. 标题应可独立理解，不超过 60 个中文字符；不要使用“微信消息”“未命名”等空泛标题。
5. 最多给出 8 个短标签。始终包含 `微信收件`，避免创建同义重复标签。
6. 若内容包含明确行动项，在正文中使用 Obsidian 待办语法 `- [ ]`。
7. 普通收藏不需要回复微信；只有信息不足、存在歧义或用户明确要求确认时才给出简短 `reply`。

API 集成要求只输出调用方指定的 JSON，不添加代码围栏或额外说明。
