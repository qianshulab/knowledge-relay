# 同步工程审计

本轮参考通用 Agent → 同步服务 → Obsidian 分层提示词，但按知流已有的单用户、令牌绑定 target、服务端权威批次架构做了适配，没有退回客户端自报 collectionId/cursor，也没有取消附件同步。

| 检查项 | 当前实现 |
|---|---|
| Agent 与同步解耦 | 原始消息先持久化并发布；Nanobot 只产生语义建议和受限 artifact |
| Agent 输出边界 | 严格字段白名单、枚举和长度限制；拒绝 path/command/script 等协议字段 |
| 永久身份 | 微信 Bot ID + 来源消息 ID；不依赖标题或模型内容 |
| 版本语义 | 服务端对物化内容、处理状态和附件哈希生成 SHA-256 |
| 增量游标 | 每个令牌绑定 target 独立维护服务端 cursor |
| 稳定分页 | 未 ACK batch 原样返回；空拉取不创建 batch |
| ACK 幂等 | 同一 batch 重复 ACK 返回相同 cursor |
| ACK 时机 | 笔记与全部附件写入并保存本地索引后才确认 |
| 本地去重 | 只按远程 ID；本地索引丢失时可扫描 frontmatter 重建 |
| 冲突保护 | 只更新托管标记区；无标记旧笔记进入冲突，不整篇覆盖 |
| 用户编辑 | 状态、tags、下一步、任务勾选、临时备注和自定义正文保留 |
| 已处理内容 | 移出收件箱后标为 processed，不自动搬回 |
| 用户删除 | 标为 dismissed，历史重放不自动复活 |
| 敏感级别 | restricted 永不写入普通 Vault，其余由本地上限控制 |
| 外部 Markdown | 移除活动 HTML、危险 URI、本地嵌入和远程图片自动加载 |
| 附件完整性 | 每个文件下载后校验服务端 SHA-256 |
| 重试 | 超时、429、5xx 最多重试 2 次；401/403 和其他 4xx 立即停止 |
| 调度 | 启动默认一次；周期同步默认关闭且最短 5 分钟；隐藏/忙碌时跳过 |
| 令牌 | 只发送到本机 HTTP 或远程 HTTPS；错误脱敏；ACK 不回传路径/正文 |
| 恢复工具 | 状态、最近错误、重建索引、双确认重置游标、打开收件箱 |
| 兼容升级 | 插件 1.4 优先请求协议 1.2，同时接收 1.0/1.1 和旧 DTO；应用内置插件版本可覆盖较旧上传包 |
| 结构化语义 | 摘要、要点、详细整理、保留原因、建议、敏感级别、置信度和警告均由服务端保存，不从模板反向推断 |

## 仍然明确保留的边界

- Obsidian 没有跨平台通用系统钥匙串接口，插件令牌保存在插件 `data.json`；需依赖 Vault 配置目录权限和服务端可撤销令牌。
- `requestUrl` 不提供统一的请求取消句柄。插件以超时停止本轮状态推进，迟到请求不会导致 ACK 或本地游标前移。
- 单用户 SQLite 部署不设计多写实例；需要横向扩展时应先迁移数据库和租约机制。
- AI 建议不自动移动、删除或改写用户知识库；高风险动作始终由用户决定。
